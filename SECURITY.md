# Безопасность сайта

Сайт остаётся публичным. Это статические страницы и демонстрационный кабинет, а не система хранения данных учеников. Для настоящего личного кабинета нужны серверная авторизация и отдельное защищённое хранилище. Публиковать документы учеников, пароли, ключи и почтовые учётные данные в этом репозитории нельзя.

## HTTPS и надпись «Не защищено»

Основной адрес: https://phystechonline.ru/ . Сертификатом и перенаправлением HTTP управляет GitHub Pages, а не HTML страницы.

Владелец репозитория должен открыть [Settings → Pages](https://github.com/bronislav20072012-alt/fiztech-online/settings/pages) и включить **Enforce HTTPS**. Если переключатель недоступен, сначала нужно дождаться выпуска сертификата для custom domain `phystechonline.ru` и устранить показанные GitHub ошибки DNS. Не следует отключать проверку сертификата или советовать посетителям обходить предупреждения браузера.

После включения нужно проверить открытие `http://phystechonline.ru/index.html#about`: сервер должен перенаправить на HTTPS, путь и якорь должны сохраниться, предупреждений о сертификате быть не должно. Проверить нужно также прямые ссылки на `method.html`, `demo.html` и `contact-success.html`.

`https.js` переводит старые HTTP-ссылки на HTTPS на известных публичных доменах. Это запасной переход в браузере: первый HTTP-ответ остаётся незащищённым, поэтому скрипт не заменяет Enforce HTTPS. Форма дополнительно отказывается отправлять данные со страницы, открытой по HTTP.

## Ограничения в браузере

На каждой HTML-странице в начале `<head>` задана Content Security Policy: скрипты, изображения, шрифты и CSS разрешены только с текущего сайта. Правило `upgrade-insecure-requests` переводит поддерживаемые браузером HTTP-запросы ресурсов на HTTPS; если HTTPS-ресурс недоступен, возврата к HTTP не происходит. Inline-скрипты и обработчики событий запрещены; произвольные сетевые подключения, встроенные страницы, плагины и подмена базового URL запрещены. Обращения могут отправляться только на этот сайт или на точный HTTPS-адрес существующей формы FormSubmit. Остальные страницы не разрешают отправку HTML-форм.

Если браузер подтверждает действительный сертификат, но сообщает о небезопасных данных на странице, нужно проверить mixed content в Console и Network средств разработчика. Открытие актуального URL в новом приватном окне помогает проверить влияние кеша, расширений и сохранённых разрешений. Для сайта не следует разрешать загрузку небезопасного содержимого. HTTP-адрес `http://www.w3.org/2000/svg` в `xmlns` и `createElementNS` — идентификатор пространства имён, а не загрузка ресурса; менять его на HTTPS нельзя.

Политика referrer передаёт внешним сайтам только origin при HTTPS-переходах, без пути и параметров. Ссылки, открываемые в новом окне, изолированы через `noopener noreferrer`. QR-коды и остальные ресурсы размещены локально. В коде приложения нет аналитики, отправки IP-адресов на почту или записи данных демо-кабинета в постоянное хранилище.

Фоновое видео шапки и его статичная обложка размещены на этом же сайте. `media-src 'self'` разрешает медиа только с текущего сайта. Видеофайл не содержит звуковой дорожки. При включённом уменьшении движения или экономии трафика остаётся статичная обложка, без загрузки MP4; при скрытии вкладки воспроизведение приостанавливается.

CSP в HTML не поддерживает `frame-ancestors`. Для полноценной защиты от встраивания в чужие страницы нужен HTTP-заголовок `Content-Security-Policy: frame-ancestors 'none'`. Дополнительные заголовки HSTS, Permissions-Policy и другие настраиваются у хостинга или обратного прокси. GitHub Pages не читает файл `_headers`; добавление такого файла не включит эти меры. Эти серверные меры в текущем репозитории не заявляются как настроенные.

## Обращения и персональные данные

Форма передаёт введённые посетителем имя, email, роль, класс и сообщение внешнему сервису FormSubmit по HTTPS после нажатия кнопки отправки. Пароли и секретные документы в форму вводить не следует. Сервис может потребовать проверку от спама; штатная проверка и скрытое поле для ботов сохранены. HTTPS не исключает обработку данных почтовым сервисом: хостинг, FormSubmit и почтовый провайдер могут вести собственные журналы.

Работу формы и доставку письма нужно проверять отдельно, как описано в README. Данные формы не помещаются нашим кодом в URL страницы благодарности. Перед запуском полноценного приёма заявок владелец должен определить применимую политику обработки данных и условия использования стороннего сервиса; этот документ не заменяет такую политику.

## Проверки при изменениях

`python3 scripts/check_security.py` проверяет CSP, внешние ресурсы, обработчики событий, адрес формы и ссылки. Workflow **Security checks** выполняет эту проверку и сканирует историю Git через Gitleaks 8.30.1. Версия сканера и контрольная сумма закреплены, checkout закреплён по SHA, права workflow ограничены чтением. Локальные файлы с типичными именами секретов исключены через `.gitignore`; это не защищает уже опубликованные или принудительно добавленные файлы.

Чтобы не публиковать изменения при провале проверки, владелец может добавить обязательный статус **Security checks / check** в правила защиты `main` с проверкой через pull request. Самостоятельный проверочный workflow не меняет существующие правила публикации GitHub Pages. Владелец также должен включить двухфакторную аутентификацию GitHub и почты школы. Пароли и токены нельзя передавать в публичных issues или исходном коде.

О возможной уязвимости сообщайте на `phystechonline3@gmail.com`, без персональных данных учеников и действующих секретов.
